# S2: real upstream editor bridge

Observed 2026-10-11 on Linux/Chromium using Bento revision
`3d6f7f1fcdf2308e875345ce4f1e0ec0820c914b` (slides package 1.2.6). This is a
bounded compatibility adapter, not an upstream fork. This evidence covers the
bridge and a temporary persistence harness; the full product persistence,
synchronization and Studio acceptance tests remain separate.

## Verified upstream contract

At this revision, `slides/src/main.ts` exposes `window.bento.doc` (live getter),
`selection` (copied IDs), `loadDoc(json)`, `undo()`, `redo()` and `serialize()`.
`loadDoc` is undoable, preserves open-file identity and returns either `false`
or an import report, including dropped fields and asynchronous text refits.
`Store.on()` exists internally but is **not exposed publicly**.

`src/bridge/browser.js` polls public document/selection snapshots (200 ms
default) and emits document, slide-order and selection observations. It
delegates undo/redo to upstream. A native undo observed by polling is a document
change; the bridge does not invent a reliable native action name. Multiple edits
between polls may coalesce. Save reads the live document immediately,
independently of the polling timer, and passes an immutable snapshot to the host
persistence hook. Its serial queue prevents out-of-order writes. Acknowledging
an older save does not clear newer unsaved changes. A failed save remains dirty
and retryable.

`load` refuses foreign identity and collaborative input. A load report with
removed fields causes upstream undo and an explicit error; the original document
must match byte-for-byte afterwards. Because no public history-reset API exists,
that refused load may remain in upstream redo history. Hosts must surface the
error and should reload from authoritative saved state before resuming editing
after a refused restore. Successful load reports remain available to the host;
font refits may cause a later observed change.

## Isolation and why it is necessary

`kernel/src/sync/session.ts` creates BroadcastChannel transport unconditionally.
It also asynchronously mints real collaboration credentials whenever `collab` is
absent, even when no connection is requested. Network blocking alone does not
prevent those credentials appearing in native saved HTML.

`prepareIsolatedDocument` therefore supplies the exact inert upstream-compatible
value `collab: {room: "", key: "", on: false}`. It contains no credentials,
prevents `ensureCollab()` minting, and upstream `sharingOn`/`stampInto` skip it.
Any other collaboration block is refused, not silently stripped. This sentinel
must be present **before upstream boots**, including for independent standalone
files.

Insert `ISOLATION_BOOTSTRAP` and `OFFLINE_CSP` before the upstream executable
loader. The bootstrap substitutes an inert BroadcastChannel in this realm,
disables WebSocket, and makes IndexedDB unavailable. This prevents same-origin
collaboration and stale browser recovery from competing with project state. The
Share button is explicitly disabled. The CSP blocks remote requests, external
assets and live iframes while permitting bundled runtime bytes and same-origin
Studio persistence. The policy is a local host capability adapter, not a
browser-profile change. Ordinary project edits need the host's durable save
hook; IndexedDB is intentionally not a second backup.

The initial upstream auto-update attempt is blocked by CSP and can produce a
console refusal; no update request reaches the external server. This is not a
failed document save. Parent integration may additionally expose upstream's
offline preference through a scoped adapter to suppress the attempt.

Native self-saving uses an upstream pristine HTML clone, so the isolation script
and meta CSP must be part of the original served HTML. Inserting them into an
already-running DOM is insufficient. A Studio-only script must not be inserted
into standalone HTML if it needs a local server after distribution.

## Reproducible checks

```sh
deno test tests/bridge_test.ts
deno check src/bridge/isolation.ts tests/bridge_live_server.ts
deno lint src/bridge tests/bridge_test.ts tests/bridge_live_server.ts
```

Seven unit cases exercise native in-place mutation observation, immutable
snapshots, slide order, selection, undo/redo, racing saves, failed-save retry,
identity refusal, lossy-load rollback and the credential-free off sentinel.
These are synthetic state/queue checks, not a claim of browser coverage.

Build the pinned upstream shell independently, then start the manual live probe:

```sh
deno run -A tests/bridge_live_server.ts \
  /path/to/pinned/Bento_Slides.bento.html /tmp/bridge-state.json
```

Open `http://127.0.0.1:8765/` in a dedicated test browser. The fixture uses a
fixed test-only docId; never reuse that ID for a real user project. Select the
first slide, select its native text box, and press ArrowRight. Inspect the
public API and bridge, call `bridge.save()`, and reload. The temporary server
writes the supplied state file but is deliberately not the product transaction
server.

## Host integration and limits

```js
import { createBentoBridge } from "./bridge/browser.js";
const bridge = createBentoBridge(window.bento, {
  docId: projectDocId,
  persist: (snapshot) => durableProjectSave(snapshot),
  onEvent: (event) => refreshInspector(event),
});
await bridge.save(); // persists design + pending edits; does not sync QMD
```

The host owns authentication/origin checks, atomic persistence, source
baselines, conflict handling, autosave scheduling, inspector UI and shutdown
warnings. This bridge exposes reliable explicit save completion; polling cannot
guarantee saving a last edit if the browser crashes before the next capture.
Native Bento retains its own dirty flag after project save (no public setter),
so its native beforeunload warning may still appear. Do not suppress it without
an equivalent verified host warning. Current-slide navigation is not exposed as
a stable public getter; only selection and slide-array order are covered.
Performance with large asset-heavy documents and macOS/Windows browser behavior
remain unmeasured.
